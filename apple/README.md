# Apple app

A Swift app for iPhone, iPad and Mac. The rows are edited natively; the
graph is the web renderer (`web/native-app`) in a WKWebView, served from the
app bundle as `equation://app/`.

- `Equation/` — the app (SwiftUI, one multiplatform target, generated by
  [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`).
- `EquationCore/` — the language in Swift, ported from `lib/` a stage at a
  time. No Foundation, so it can also build for WebAssembly.
- `corpus/` — records what the TypeScript suite asks the parser, so the Swift
  port is held to the same answers.

## Build

```sh
pnpm app:web                          # the renderer, into Equation/WebBundle
xcodegen -s apple/Equation/project.yml
open apple/Equation/Equation.xcodeproj
```

Debug builds open straight onto a graph, skipping the document browser, with
`EQUATION_SCRATCH` set (rows separated by `;`):

```sh
SIMCTL_CHILD_EQUATION_SCRATCH='y = sin(a x); a = 2' xcrun simctl launch booted io.equation.app
```

## The renderer bridge

Swift calls `window.equationApp` (`loadRows`, `editRows`, `setSlider`,
`setTheme`); the page posts `ready`, `rows` (it rewrote rows itself: a slider,
a dragged point) and `status` (each row's color, error, readout and slider) to
the `equation` message handler. See `web/native-app.ts`.

## Core conformance

```sh
pnpm swift:test    # re-record the corpus from the TypeScript suite, then swift test
```
